# DevDock — 本地项目启动器

## 一句话

给 Windows 开发者用的桌面启动器：录入项目路径和命令，一键搭环境、一键启动，并记住上次的环境直到你切换到下一个项目。

## 用户与场景

- 同时在多个本地仓库之间来回切换的开发者。
- 每次重新开工都要回忆「这个项目怎么装依赖、怎么起服务、要设哪些环境变量」。
- 想要一个地方统一看日志、统一停进程，而不是开五个终端窗口。

## 要解决的问题

1. 项目启动知识散落在 README、历史命令、脑子里 → 集中成可复用档案。
2. 每次启动重复输命令 → 一键执行。
3. 多项目并行导致环境变量串味、进程残留 → 同一时间只有一个活跃环境，切换即清理。
4. 启动失败看不到原因 → 内联实时日志 + 落盘日志。

## 非目标（v1 明确不做）

- 不做通用包管理器，不替代 npm / pip / uv。
- 不做远程服务器 / SSH 部署。
- 不做 Linux / macOS 适配（代码留隔离层，v1 只保证 Windows）。
- 不做 AI 代码生成、不做云同步。
- 不做多开同一项目的多个实例。

## 关键约束

- Electron + 原生 HTML/CSS/JS，无前端构建链，`npm start` 即可跑。
- 进程隔离：主进程持有全部 child_process，渲染进程零 Node 权限（contextIsolation）。
- 环境隔离：启动时只注入子进程环境；可选同步 `.env`（带自动备份/还原）。
- 数据默认存放于 `%APPDATA%/DevDock`，删除应用不丢用户档案（用户显式触发清理除外）。

## 成功标准

- 新增一个 Node 项目 → 自动检测出安装/启动命令 → 点「搭环境」成功 → 点「启动」看到服务日志。
- 从项目 A 切到项目 B，A 的进程全部退出，A 注入的 `.env` 被还原。
- 关掉应用再打开，上次活跃项目仍是活跃状态，档案完整。
- `npm test` 全绿；`npm run dist` 产出可安装的 `.exe`。
